# hare-orm

An async Python ORM for PostgreSQL and SQLite, built with relations in mind. `hare-orm` is a
heavily reworked fork of tortoise-orm, close enough to Django's ORM in shape that Django users will
feel at home — models are plain classes, queries are built lazily through a `QuerySet`, and
migrations are generated by diffing model state.

What sets it apart:

- **[Pluggable dialects](dialects/dialects-and-features.md).** SQLite and PostgreSQL are dialects built on the
  same public API a third-party package uses: SQL, column types, DDL, introspection and what each
  server version supports come from the dialect. A database without transactions, foreign keys or
  unique constraints gets explicit errors instead of silently wrong results, and a model may have
  no primary key. See [Writing a dialect](extending/writing-a-dialect.md).
- **A Rust PostgreSQL driver** (`hare.dialects.postgresql.drivers.rust_pg`) is the default for
  `postgresql://` URLs, decoding rows and converting values in Rust rather than pure Python; the
  pure-Python `asyncpg` driver is available as `postgresql+asyncpg://`.
- **Composite primary keys are first-class** — including as foreign-key targets, with real
  table-level `FOREIGN KEY` constraints, cascades, joins and `prefetch_related()` support.
- **Optimistic locking, soft delete and dirty-field tracking are native `Meta` options**, not
  hand-rolled mixins.
- **Declarative DB triggers and constraints** (`Meta.triggers`, `Meta.constraints`) are actually
  applied by `CreateModel` when a migration runs.
- **[PostgreSQL's own types and indexes](dialects/postgresql/fields.md)** — `ArrayField`,
  `PostGISField`, `TSVectorField`, `VectorField` (pgvector similarity search), range fields,
  full-text search, and the GIN/GiST/BRIN/Bloom/Hash/SP-GiST/IVFFlat/HNSW index family.
- **[Request queries](integrations/request-queries.md)** (`hare.contrib.request_query`) — a validated,
  paginated query built from the parameters of an HTTP request, with
  [Litestar](integrations/litestar.md), [FastAPI](integrations/fastapi.md) and
  [Robyn](integrations/robyn.md) integrations.
- **A [transactional outbox](integrations/outbox.md)** (`hare.contrib.outbox`) — publish an event in
  the same transaction as the write it describes, with a background relay to actually deliver it.
- **Built-in [multi-tenancy](soft-delete-versions-tenants/multi-tenancy.md)** (`Meta.tenant_field`) — every default-manager
  query on an opted-in model is scoped to the active tenant automatically, the same way
  `Meta.soft_delete_field` already scopes out deleted rows.
- **A runtime [repeated-query detector](observability/repeated-queries.md)**
  flags N+1 query patterns as they happen, not just in tests.

## Quick example

```python
from hare import fields
from hare.models import Model


class Author(Model):
    id = fields.UUIDField(primary_key=True)
    name = fields.CharField(max_length=120)
    email = fields.CharField(max_length=254, unique=True, null=True)

    class Meta:
        table_description = "Book authors"


async def main() -> None:
    author = await Author.objects.create(name="Ursula K. Le Guin")
    async for a in Author.objects.filter(name__icontains="le guin"):
        print(a.name)
```
