# Поиск расхождений

`hare drift [app_labels...] [--connection ALIAS] [--schema SCHEMA]` сравнивает текущую схему базы с
моделями: печатает каждое расхождение — операцию, которая его устранит, неизвестную таблицу или
колонку, колонку типа, который модели не могут выразить, — и завершается с кодом 1, если оно есть, и
с кодом 0, если нет. Без `--connection` проверяется первое настроенное подключение, без меток
приложений — каждое приложение на нём.

```bash
hare drift --connection default
```

## <a id="from-code"></a>Вызов из кода

Команда — тонкая обёртка над публичной функцией библиотеки; вызывайте её напрямую (например,
из проверки работоспособности или в CI), а не через командную строку:

```python
from hare.migrations.drift import detect_drift_for_alias

async def detect_drift_for_alias(
    apps: Apps,
    apps_config: dict[str, dict[str, Any]],
    connection_alias: str,
    *,
    schema: str | None = None,
    app_labels: list[str] | None = None,
) -> DriftResult

result = await detect_drift_for_alias(Hare.apps, apps_config, "default")
if result.has_drift:
    ...
```

Проверяется каждое приложение на подключении `connection_alias`: приложение из `apps_config`, у которого
`default_connection` равно `connection_alias`, а также приложение, зарегистрированное только во время работы
(например, через `Hare.register_live_models()`), модели которого привязаны к `connection_alias`. `app_labels`
сужает проверку до этих приложений. Модель с `Meta.managed = False` (в том числе зарегистрированная во
время работы) никогда не сравнивается, но её таблица считается известной и поэтому не попадает в
неизвестные. Модель без `Meta.schema` всегда ищется в схеме подключения по умолчанию (`current_schema()`
в PostgreSQL, то есть первая существующая схема в `search_path`) — там, где её таблицу создаёт
`migrate`; модель с `Meta.schema` ищется в своей схеме. `schema` только выбирает схему, в которой
ищутся неизвестные таблицы (при `None` — схема по умолчанию), и в базе без схем (SQLite, ClickHouse) не учитывается. Схемы и
расширения, которые нужны только моделям приложений вне проверяемых, никогда не сообщаются. Ошибка
`ConfigurationError` — для неизвестного подключения, неизвестного элемента `app_labels` или
подключения, которым не пользуется ни одно приложение.

## <a id="what-is-compared"></a>Что сравнивается

Кроме колонок, индексов, ограничений и триггеров, сравнивается запись диалекта подключения в
[`Meta.table_options`](../models/meta-options.ru.md#table_options) с тем, как хранится таблица. У
[партиционированной таблицы](../models/meta-options.ru.md#partitioning) из каталога читаются
стратегия, ключ и каждая партиция с её границей: партиция, добавленная или удалённая вручную,
показывается как `RemovePartition`/`AddPartition`, другая стратегия или ключ — как
`AlterModelOptions`. Параметры хранения берутся с партиций; параметр, который у них различается,
показывается со значением каждой партиции. Сами партиции никогда не считаются отдельными таблицами
— ни в `drift`, ни в `inspectdb`, который записывает `partitioning=` таблицы в `Meta.table_options`.

Смотрите `DriftResult.operations`/`.untracked_tables`/`.untracked_columns`/`.mismatched_columns` или
просто свойство `.has_drift`.

Каждая колонка сравнивается со своим полем: у обычного поля — тип, допустимость `NULL` и объявленный
`db_default`; у внешнего ключа — допустимость `NULL`, индекс, ограничение `FOREIGN KEY` (есть ли, на
таблицу ли связанной модели, с действием `ON DELETE` поля) и `db_default`. Разница возвращается как
`AlterField`, который вернул бы поле к объявленному виду; при другом типе — от поля, которым
`inspectdb` восстановил бы колонку (`CharField`/`DecimalField`, отличающиеся только размером,
сохраняют свой класс). Типы сравниваются по нормализованным названиям PostgreSQL
(`varchar`/`character varying`, `int4`/`integer`, `timestamptz`/`timestamp with time zone`, ...), в
SQLite — по типовому сродству: колонки `VARCHAR(50)` и `VARCHAR(10)` там одинаковы. Значение по
умолчанию сравнивается по тексту без учёта регистра, пробелов, скобок и приведений типов (`'a'::text`
равно `'a'`, `CURRENT_TIMESTAMP` равно `Now()`); значение типа, у которого нет нормализованного вида
(дата, документ JSON), не сравнивается. Тип или значение по умолчанию, которые ни одна сторона не
может нормализовать, считаются неизменными, поэтому в схеме, только что созданной `migrate` или
`generate_schemas()`, расхождений никогда нет. Для колонки ключа внешнего ключа, тип которой отличается
от типа ключа связанной модели, нет `AlterField`, который бы её описал; она сообщается как
`ColumnMismatch` (`app_label`, `model_name`, `table`, `column`, `detail` — например, «type is bigint,
the model expects integer») в `.mismatched_columns`, как и колонка такого типа, для которого у
`inspectdb` нет поля.

`ManyToManyField`, у которого нет промежуточной таблицы, которой управляет hare, или в ней нет одной
из колонок ключей, или нет её ключа `UNIQUE`, сообщается как `AddField` для этого поля; поле, в
промежуточной таблице которого нет индекса ключа, объявленного его `db_index`, и `ForeignKeyField`,
у колонок ключа которого нет своего индекса, — как `AlterField`. Условие частичного индекса
сравнивается по смыслу, а не по тому, как база сама записала условие; условие, которое не удаётся
разобрать обратно, считается объявленным условием одноимённого `PartialIndex` по тем же полям.

Уникальный индекс в базе сопоставляется с объявленным `UniqueConstraint` (с `condition` или без) или
`Index(unique=True)`, который он реализует, — сначала по имени, потом по колонкам, — поэтому ни
индекс по одной колонке, ни индекс, который SQLite создаёт сам (`sqlite_autoindex_*`), не выглядит
как поле с `unique=True` или второе ограничение; `deferrable`/`initially_deferred` у
`UniqueConstraint` тоже сравниваются (PostgreSQL). Безымянный индекс — и индекс по выражению тоже —
сопоставляется под именем, которое hare для него создаёт. У триггера, у которого время срабатывания,
`for_each`, события, язык и отложенность совпадают с объявленным триггером того же имени,
используется объявленный текст `when`, если он есть у обоих (PostgreSQL его переписывает), и
объявленный `body`, если они совпадают без пробелов по краям; любое другое различие сообщается.

Функция, которую она оборачивает, принимает уже построенное состояние:

```python
async def detect_drift(
    connection: DatabaseClient,
    new_state: State,
    target_labels: list[str],
    schema: str | None = None,
    unmanaged_model_states: list[ModelState] | None = None,
) -> DriftResult
```
